# 2.2-alpha.52-six1 测试版

以 alpha.51-language1 为基线，参考上游 master `73147c8` 的六项选定功能；没有合并整个上游版本。目标仍为 N67 国行 3.1.190。

## 操作与改动

1. **列表效能**：应用／排除列表先建立 2 条应用行，再每次空闲 tick 补 2 条，保持每页 6 条的操作方式。批量页勾选、全选和进度更新只修改变化的标签；删除造成列表结构变化或切页时才重建。
2. **打开隐藏应用**：应用管理 → 应用详情 → 打开应用。延后到 tick 提交原生启动请求，不改变显隐策略或应用排序。提示“已提交打开请求”只表示提交，不能保证快应用本身启动成功。
3. **容量**：原本 96 项总容量包含系统项；现在可管理条目上限 192、原始注册链走访上限 256，保留 64 KB 元数据上限。超限不执行批量修改。NAM1 策略格式保持不变；旧版不支持超过 96 条策略，回退前请留意。
4. **日志**：显示最新 8 KB 范围内最多 200 条完整记录，最新在前，长文字换行；写入截断保持 UTF-8 完整。批量勾选不再逐次写通用点击日志，实际显隐操作仍保留日志。
5. **蓝牙名称**：Chaos → 设置 → 更多设置 → 蓝牙名称，使用键盘编辑并确认。仅在服务就绪且接口表匹配时提交；读取确认后才提示名称已更新。手机缓存可能稍后才刷新，与“系统关于”里的设备名称互不影响；重启保持效果待实机确认。
6. **屏幕翻转**：同一页面点击“屏幕方向”在正常／180°间切换。使用 9 Pro 的原生显示旋转处理，不是单独旋转 Chaos 控件。再点一次恢复；重启后可能恢复默认。不包含开机自启动。

投递包兼容修复现位于“更多设置”，原功能保留，既有 alarm.dat 问题不宣称已解决。

## 验证边界

新增测试执行重定位后的 ARM 程式，并执行实际固件的启动请求生成器、蓝牙 BTM 包装函数及 LVGL8 旋转主体。GUI、文件系统、蓝牙底层和硬件是替身，不能等同于实机通过。

容量测试含 192 项浏览、193 项拒绝、80 个原生项加 64 个用户应用的批量保护，以及 65536／65537 字节元数据边界。另检查单选／全选不会销毁原控件树、隐藏启动不改变排序／策略、日志 UTF-8 和高度上限。

实机重点：蓝牙名称在手机端的显示、重启后行为，以及翻转后画面刷新和触摸位置是否一致。若画面异常可重启恢复；本版不持久化旋转配置。
