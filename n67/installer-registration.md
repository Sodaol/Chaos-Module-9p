# 2.2-alpha.10 桌面图示恢复

实机状态 S3 B18 / T85 A80 N1 C2 说明 S3 是历史状态，当前 in_list 已为零。
不能据此确认是谁移除了图示。旧程序有两个确定的恢复缺陷：图示丢失不退回阶段2，
而手动重试只重置阶段2；重新打开安装器只检查应用注册，已注册便提前返回。

## 本次修正

- 每次发现桌面项丢失立即退回阶段2，清除旧 tile，不再保留历史成功状态。
- 手动重试允许重置阶段2，亦兼容旧阶段3但 in_list 为零的耗尽状态；有效桌面项不重置。
- 已驻留分支建立仅含注册上下文的恢复任务，复用已存在的应用，不读取、解压或初始化新的 Rust 模组。
- 原生新增前重新核对应用节点、ID 和非空图示来源，缺少节点/图示分别显示 B21/B22。
  对已核对的当前应用仅清除 hidden 位0，保留其他位；不修改其他应用。
- 失败额外显示 L（桌面链头记录的链接偏移，应为18十六进制）与 I（当前桌面节点指针）。
  增加资讯用于继续定位实机原因，并不宣称已查明原始移除来源。

## 验证

三个 ARM 装载地址执行真实固件 launcher add、排序及链表指令，覆盖图示丢失、
本应用 hidden 位恢复、其他位保留、重复检查不重复新增、分配失败时撤销旧成功状态，
以及分配恢复后再新增并保持顺序。Lua 验证已驻留恢复不展开新镜像、复用单一 timer、
失效阶段3可重试但有效桌面项不可重置。OS、分配器和 LVGL 仍为测试替身，尚待实机确认。

# 2.2-alpha.9 注册重试与状态诊断

实机照片显示安装器走到等待注册的最终超时，但没有阶段、回调计数等信息，
不能仅据此确定是定时器没执行、注册被拒绝还是桌面列表未建立。

## 本次处理

- 修正原生指针范围不一致：C 注册器接受 SRAM `0x20000000..0x20100000`
  和 PSRAM，Lua 的已驻留/桌面项完成判断却只接受 PSRAM。现在两处完成判断
  与注册器一致，仍检查对齐和完整读取范围。分配、所有权与内存写入限制未放宽。
- 首次等待期间发现注册回调仍未执行时，只唤醒既有 Lua bootstrap timer 一次。
  手动重试复用同一 bridge/native timer slot，不重新分配注册器。
- 已注册、等待桌面图示且 80 次新增尝试耗尽时，手动重试可重置该尝试计数。
  已完成的应用不会重置，也不把等待状态标为成功。
- 逾时显示三行状态，去除遮挡资讯的 main.lua 完整路径：

```
注册未完成 S… B…
T… A… N… C…
请拍此状态反馈
```

S：注册阶段；B：原生 breadcrumb；T：注册 timer 回调次数；
A：新增图示尝试次数；N：是否已有原生 timer；C：bootstrap 状态。
例如 S0/T0/N0/C0 表示还没有观察到 timer bootstrap 或注册回调执行；
S2 表示应用已注册，仍在等待桌面项。必须阶段 S3 且桌面指针有效才显示成功。

实际卡住的阶段仍需用户安装新版后的状态确认，不能把此版描述为已完成实机修复。

## 验证

实际打包的 Lua 测试覆盖 SRAM/PSRAM 已驻留判断、SRAM 桌面节点成功、
停滞 bootstrap 唤醒后的恢复、仍停滞时的有界失败与状态内容、图示尝试计数重置、
不重复创建 timer 及损坏上下文拒绝。其余原生、GUI 与存储仍遵循桌面模拟范围。
